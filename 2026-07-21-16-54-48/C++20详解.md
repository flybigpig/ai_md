## 0. C++20 为什么重要

C++11 把 C++ 现代化，C++20 则是**自 11 之后最大的一次语言变革**。它一口气交付了四个范式级特性：

| 特性 | 解决的老痛点 |
|------|--------------|
| **Concepts** | 模板报错是"天书"，约束只能靠 SFINAE 黑魔法 |
| **Ranges** | 算法必须手写 `begin()/end()` 对，组合困难 |
| **Coroutines** | 异步/惰性计算只能自己写状态机或用回调地狱 |
| **Modules** | `#include` 文本拷贝、编译慢、宏污染、ODR 雷区 |

外加 `std::format`、`std::span`、三路比较 `<=>`、`std::jthread` 等"早该有"的实用件。下面从最易上手的部分讲起。

## 1. 基础层：每天都会用到的语法糖

这些不需要理解复杂理论，立刻能提升代码质量。

### 1.1 三路比较运算符 `<=>`（spaceship）
一行自动生成全部 6 个比较运算符。

```cpp
struct Point {
    int x, y;
    auto operator<=>(const Point&) const = default;  // 自动生成 == < > <= >= !=
};

Point a{1,2}, b{1,3};
bool r1 = a < b;   // true，字典序比较成员
bool r2 = a == b;  // false
```
- `= default` 按**声明的成员顺序**逐个比较。
- 返回类型决定强弱：`std::strong_ordering` / `weak_ordering` / `partial_ordering`。
- 手写：`auto operator<=>(const T& o) const { return x <=> o.x; }`，用 `std::strong_ordering::less` 等返回。

### 1.2 `std::format` —— 终于能用的格式化
告别 `printf` 的类型不安全，也告别 `cout` 的啰嗦。

```cpp
#include <format>
std::string s = std::format("{} + {} = {}", 2, 3, 5);
// 格式说明符接近 Python：{:>4} {:08.2f} {:%Y-%m-%d}
std::cout << std::format("{:08.2f}\n", 3.14159);   // 00003.14
```
> 注意：`std::print`（直接输出到流）是 **C++23** 才加，C++20 只有 `std::format` + `std::cout <<`。

### 1.3 `std::span` —— 零拷贝的连续序列视图
函数接口不要再 `void f(const T* data, size_t n)` 了，用 `span` 更安全和表达力强（**不拥有内存**）。

```cpp
#include <span>
void process(std::span<const int> s) {
    for (int x : s) { /* ... */ }
}
int arr[4] = {1,2,3,4};
std::vector<int> v{5,6,7};
process(arr);   // OK，自动从数组构造
process(v);     // OK，从 vector 构造
process({arr, 2});  // 子区间
```
- `span` 是**非拥有**视图，生命周期由调用方负责（别返回局部数组的 span）。
- 对标 Rust 的 `&[T]`、Go 的 slice。

### 1.4 设计器初始化（designated initializers）
按成员名初始化（C 语言早有，C++20 才引入，仅限聚合类型）。

```cpp
struct Config { int timeout; bool verbose; };
Config c{.timeout = 30, .verbose = true};   // 顺序可任意，按名字
```

### 1.5 Lambda 增强
- **模板 lambda**（C++20 正式支持，之前要泛型靠 `auto` 参数）：
  ```cpp
  auto f = []<typename T>(std::vector<T>& v) { /* T 可见 */ };
  ```
- **`[=, this]` 弃用**：隐式捕获 `*this` 现在需要显式 `[=]` 在 lambda 内拷贝整个对象（避免悬挂 `this`）。
- **无状态 lambda 可默认构造/可赋值**（用于作为无状态函数对象）。

### 1.6 其他小语法
- `for (auto [k,v] : map)`（C++17 已有）配合 `if (init; cond)` 更顺。
- `using enum`（C++20）：把 enum 成员引入作用域。
  ```cpp
  enum class Color { Red, Green };
  using enum Color;   // 之后直接写 Red / Green
  ```
- `[[likely]]` / `[[unlikely]]`（C++20）：分支预测提示，热路径优化。
  ```cpp
  if (rare) [[unlikely]] { handle_error(); }
  ```
- 允许 `char8_t` 用于 UTF-8（新类型，注意和 `char` 不再隐式转换）。

## 2. 核心一：Concepts（概念）

> **这是 C++20 最该先学的核心特性。** 它把"模板参数必须满足什么"从注释变成编译期可检查约束。

### 2.1 痛点回顾（SFINAE 黑魔法）
C++17 想约束模板，得写这种鬼东西：
```cpp
template <typename T, typename = std::enable_if_t<std::is_integral_v<T>>>
T add(T a, T b) { return a + b; }
// 报错时是一屏幕模板展开，根本看不出"T 不是整数"
```

### 2.2 用 Concept 改写
```cpp
#include <concepts>

template <std::integral T>   // 直接约束 T 必须是整数
T add(T a, T b) { return a + b; }

// 或自定义 concept
template <typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;   // a+b 的结果能转成 T
};

template <Addable T>
T sum(T a, T b) { return a + b; }
```
- **报错可读**：`add(std::string{}, ...)` 直接说"不满足 integral 约束"。
- **可组合**：`concept C = A && B && !C;` 用逻辑运算符组合。
- **标准库已给一批**：`std::integral` / `std::floating_point` / `std::signed_integral` / `std::same_as` / `std::derived_from` / `std::invocable` / `std::ranges::range` 等（`<concepts>`）。

### 2.3 三种使用姿势
```cpp
// 1. 简写（最常用）
template <std::integral T> void f(T);

// 2. requires 子句
template <typename T> requires std::integral<T> void f(T);

// 3. 函数体前 requires（多约束时清晰）
template <typename T>
void f(T) requires std::integral<T> && std::copyable<T>;
```

### 2.4 `requires` 表达式的两种用法
```cpp
// A. 作为 concept 的定义（上面的 Addable）
// B. 在函数内做编译期 if
template <typename T>
void serialize(T v) {
    if constexpr (requires { v.to_json(); }) {
        v.to_json();
    } else {
        static_assert(std::is_arithmetic_v<T>, "unsupported");
    }
}
```

> **实战建议**：库接口、泛型算法一律用 concept 约束；业务代码至少给关键模板加 concept，把"运行时崩溃"提前到"编译期报错"。

## 3. 核心二：Ranges（范围库）

> 把"迭代器对"升级成"可组合的数据管线"。写算法像写 Unix 管道。

### 3.1 旧写法 vs 新写法
```cpp
// C++17：找偶数并平方，写三遍迭代器，还生成临时 vector
std::vector<int> tmp, res;
std::copy_if(v.begin(), v.end(), std::back_inserter(tmp), [](int x){return x%2==0;});
std::transform(tmp.begin(), tmp.end(), std::back_inserter(res), [](int x){return x*x;});

// C++20 Ranges：一条管线，惰性求值
#include <ranges>
using namespace std::views;
auto r = v | filter([](int x){return x%2==0;})
          | transform([](int x){return x*x;});
for (int x : r) std::cout << x << ' ';   // 只有真正遍历时才计算
```

### 3.2 常用 `views`（适配器）
| view | 作用 |
|------|------|
| `filter(pred)` | 过滤 |
| `transform(fn)` | 映射 |
| `take(n)` / `drop(n)` | 取前 n / 跳过前 n |
| `reverse` | 反转 |
| `keys` / `values` | 取 map 的键/值（配合结构化绑定） |
| `enumerate`（C++23） | 带下标遍历 |
| `iota(0, n)` | 生成整数序列 |
| `split` / `join` | 切分/展平 |

### 3.3 惰性 + 组合的力量
```cpp
// 前 5 个平方数
for (int x : std::views::iota(1)
            | std::views::transform([](int i){return i*i;})
            | std::views::take(5)) {
    std::cout << x << ' ';   // 1 4 9 16 25
}
```

### 3.4 注意事项
- **惰性**：`filter`/`transform` 不拷贝数据，遍历时才算；不要在遍历期修改原容器。
- **返回的是 view 对象**，生命周期：view 依赖原 range，原 range 不能提前析构。
- 算法也可走 `std::ranges::sort(v)` 形式（直接传容器，不用 `begin/end`）。
- 投影（projection）参数：`std::ranges::sort(people, {}, &Person::age);` 按成员排序。

## 4. 核心三：Coroutines（协程）

> C++20 给了**语言机制**（关键字 + 编译器生成状态机），但标准库只附带了最基础的 `coroutine_handle`，完整设施（`generator`/`task`）要等 C++23 的 `std::generator` 或第三方（cppcoro/ folly）。

### 4.1 三个关键字
- `co_await expr`：挂起当前协程，等 expr 恢复。
- `co_yield value`：产出值并挂起（类似 Python generator）。
- `co_return value`：结束协程并返回。

### 4.2 最小生成器示例
```cpp
#include <coroutine>
#include <iostream>

struct Generator {
    struct promise_type {
        int current;
        auto get_return_object() { return Generator{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        auto initial_suspend() { return std::suspend_always{}; }
        auto final_suspend() noexcept { return std::suspend_always{}; }
        void unhandled_exception() { std::terminate(); }
        auto yield_value(int v) { current = v; return std::suspend_always{}; }
        void return_void() {}
    };
    std::coroutine_handle<promise_type> h;
    ~Generator() { if (h) h.destroy(); }
    int next() { h.resume(); return h.promise().current; }
    bool done() const { return h.done(); }
};

Generator range(int n) {
    for (int i = 0; i < n; co_yield i) {}   // 每次 yield 挂起
}

int main() {
    auto g = range(3);
    while (!g.done()) std::cout << g.next() << ' ';   // 0 1 2
}
```
> 这套 `promise_type` 样板就是为什么**日常用协程几乎都靠库**（C++23 的 `std::generator` 已封装好）。

### 4.3 协程的本质（专家视角）
- 编译器把含 `co_await` 的函数**改写成状态机**：局部变量搬到堆分配的"协程帧"，挂起时保存现场，恢复时从断点继续。
- **不是 OS 线程**：单线程内可挂起上万个协程，适合高并发 I/O、游戏逻辑、惰性序列。
- 代价：协程帧默认堆分配（可用 `std::coro_allocator` 思路自定义分配器优化）。

### 4.4 什么时候用
- 异步 I/O、网络服务器、事件循环、惰性/无限序列、状态机。
- **不需要**用协程替代普通函数或 `std::thread`——它解决的是"大量并发等待"的问题。

## 5. 核心四：Modules（模块）

> 替代 `#include` 的文本拷贝，编译更快、隔离更好、无宏泄漏。

### 5.1 基本语法
```cpp
// math.cppm  （模块接口单元）
export module math;
export int square(int x) { return x * x; }
export namespace math {
    int cube(int x) { return x * x * x; }
}

// main.cpp
import math;
int main() { return square(3); }
```
- `export module` 声明模块接口；`export` 标记对外可见符号。
- `import` 代替 `#include`。

### 5.2 模块分区（大库拆分）
```cpp
export module mylib:io;     // 分区
export void log(const char*);
// 主接口里汇合：module mylib; export import :io; export import :net;
```

### 5.3 利弊 & 现状
- **优点**：编译速度显著提高（头文件不再重复解析）、宏不会跨模块泄漏、ODR 更安全。
- **缺点**：构建系统（CMake/Bazel）支持仍在完善；和老代码 `#include` 混用有边界（可用 `module; #include <old.h> export {}` 桥接）。
- **你的现实**：AOSP / NDK 主流工程仍是头文件 + `#include`，Modules 在新独立库里才划算。不要为了"时髦"把系统代码全改 modules。

## 6. 库新增：format / span / 并发原语

### 6.1 `std::format`（已讲，见 1.2）
### 6.2 `std::span`（已讲，见 1.3）

### 6.3 `std::jthread` —— 自动 join 的线程
```cpp
#include <thread>
void worker(std::stop_token st) {
    while (!st.stop_requested()) { /* 可被外部 request_stop() 中断 */ }
}
std::jthread t(worker);
// 离开作用域时自动 request_stop() + join()，不再担心忘记 join 导致 terminate
```
- 内置 `std::stop_token` / `std::stop_source`，可协作式取消。

### 6.4 并发原语 trio
```cpp
#include <latch> <barrier> <semaphore>
std::latch done(3);          // 计数到 0 才放行
std::barrier bar(4);         // 多阶段同步点
std::counting_semaphore<10> sem;  // 最多 10 个并发
```
- `latch`：一次性倒数门闩（等 N 个任务完成）。
- `barrier`：可复用的多阶段屏障（并行算法常用）。
- `semaphore`：经典信号量，控制并发度。

### 6.5 原子与位操作
- `std::atomic<T>` 支持**浮点**和**智能指针**原子。
- `std::atomic_ref<T>`：把普通变量当作原子访问（不改原类型）。
- `std::bit_cast`（C++20）：类型双关的安全替代（取代 reinterpret_cast 踩严格别名）。
  ```cpp
  float f = 3.14f;
  uint32_t bits = std::bit_cast<uint32_t>(f);   // 安全的位重解释
  ```
- `<bit>`：`std::popcount` / `std::countr_zero` / `std::rotl` 等（编译期可用）。

### 6.6 `std::ranges::` 算法
`std::ranges::sort(v)`、`std::ranges::find`、`std::ranges::count` 等——直接吃容器，还支持投影参数，见 3.4。

## 7. 其他语言改动速记

| 特性 | 说明 |
|------|------|
| `constinit` | 强制变量在编译期初始化（区别于 `constexpr` 的"可在编译期"）。 |
| `consteval` | 函数**必须**在编译期求值（比 `constexpr` 更严格）。 |
| `std::source_location` | 获取调用点文件/行号（替代 `__FILE__/__LINE__` 宏）。 |
| 非类型模板参数支持 `auto` | `template<auto V> struct C {};` 可传任意常量。 |
| 类模板参数推导增强（CTAD） | `std::vector v{1,2,3};` 自动推 `vector<int>`。 |
| 允许在 `new` 表达式中带初始化列表 | `new std::vector<int>{1,2,3}`。 |
| `std::ssize` / `std::size` | 带符号长度 / 长度，避免 `size_t` 与 int 比较告警。 |

```cpp
consteval int sq(int x) { return x * x; }   // 必须编译期
static_assert(sq(5) == 25);

template<auto V> struct Constant { static constexpr auto value = V; };
Constant<42> c1; Constant<'x'> c2;
```

## 8. 编译器支持 & 怎么开启

```bash
# GCC 10+（特性逐步：Concepts GCC 10，Modules GCC 11 实验，Ranges GCC 10/11）
g++ -std=c++20 main.cpp -o app

# Clang 10~14 逐步完整，libc++ 支持最好
clang++ -std=c++20 -stdlib=libc++ main.cpp -o app

# MSVC 19.2x / 19.3x 基本完整
```

- **关键里程碑**：Concepts、Ranges、Coroutines 在 GCC 10/11、Clang 10~13、MSVC 19.2x 分阶段落地。Modules 支持最晚、最不稳。
- 不确定某特性支持度：查 **cppreference** 的"Feature testing"或编译器支持表，或用 `__cpp_concepts` / `__cpp_lib_format` 等特性测试宏。

CMake 开启：
```cmake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
```

## 9. 与 AOSP / Android NDK 的关系

| 项目 | 状态 |
|------|------|
| **NDK r23+** | 支持 C++20 大部分特性（用 libc++）。 |
| **NDK r21/r22** | 默认 C++17，需显式设 `APP_CPPFLAGS=-std=c++20` 且工具链够新。 |
| **Modules** | NDK 上**不建议**用于系统代码，构建系统支持有限。 |
| **Coroutines** | 可用，但标准 `std::generator` 是 C++23；NDK 若只到 20，需自己写 `promise_type` 或用第三方库。 |
| **`<=>` / format / span / concepts** | 在 NDK r23+ 均可用，强烈推荐。 |

### 落地建议（针对你研究 native 层）
1. **接口边界仍是 C 或稳定 ABI 类型**：即便用 C++20，跨 `.so` 传 `std::vector`/`std::string` 依然危险（libc++ 版本不一致会崩）。Concepts/Ranges 只在**模块内部**用，对外暴露的 API 保持 C 风格或 `android::` 稳定类型。
2. **优先采用的小特性**：`<=>`、`std::format`、`std::span`、`std::jthread`、`std::bit_cast`——它们零 ABI 风险、立刻涨可读性。
3. **谨慎采用的核心件**：
   - Concepts：内部泛型代码随便用，收益大。
   - Ranges：算法代码可用，但注意惰性 view 的生命周期（别让 view 引用已析构的临时容器——这在 native 库里是经典隐患）。
   - Coroutines：仅在明确的异步/惰性场景用，且确认 NDK 版本提供实现；否则自写 `promise_type` 增加复杂度。
   - Modules：系统级代码先别动，留给独立新库。

### 一句话路线图
> **C++20 在 Android native 上的务实用法 = "小特性全开 + Concepts/Ranges 内部用 + Modules/Coroutines 按场景谨慎上"**，ABI 边界纪律不因语法升级而放松。

## 10. 学习顺序建议（递进）

1. 先上 **`<=>`、`std::format`、`std::span`、`using enum`**（半天就能用上）。
2. 再啃 **Concepts**（写几个自己的 concept，重构一个旧模板）。
3. 然后 **Ranges**（把代码里 `copy_if`+`transform` 链改成 `|` 管线）。
4. 有异步/惰性需求再学 **Coroutines**（建议直接用 C++23 `std::generator` 或 cppcoro，别从 `promise_type` 手写起步）。
5. **Modules** 等构建系统成熟、且你正好开新库时再迁移。

> C++20 的四大件不是"都要用"，而是"在正确的场景用正确的那个"。先从每天用得到的语法糖获益，再按痛点引入核心特性。
