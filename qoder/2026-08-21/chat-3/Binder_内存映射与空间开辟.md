# Binder 内存映射与空间开辟详解

---

## 一、整体流程概览

Binder 的内存映射分为两个阶段：

```
阶段 1: mmap 映射（一次性开辟大块空间）
═══════════════════════════════════════════
  用户态 mmap() ──▶ 内核 binder_mmap() ──▶ 分配物理页 + 建立页表映射

阶段 2: 事务缓冲区分配（在已映射区域中切分）
═══════════════════════════════════════════
  binder_transaction() ──▶ binder_alloc_buf() ──▶ 红黑树查找空闲区域 + 切分
```

```
  ┌─────────────────────────────────────────────────────────────────────┐
  │                                                                     │
  │  进程启动时                    每次事务时                            │
  │  ┌──────────────┐            ┌──────────────────┐                  │
  │  │ open(/dev/   │            │ ioctl(BINDER_    │                  │
  │  │   binder)    │            │  WRITE_READ)     │                  │
  │  └──────┬───────┘            └────────┬─────────┘                  │
  │         │                             │                            │
  │         ▼                             ▼                            │
  │  ┌──────────────┐            ┌──────────────────┐                  │
  │  │ mmap(size)   │            │ binder_transaction│                 │
  │  └──────┬───────┘            └────────┬─────────┘                  │
  │         │                             │                            │
  │         ▼                             ▼                            │
  │  ┌──────────────┐            ┌──────────────────┐                  │
  │  │ binder_mmap()│            │ binder_alloc_buf │                  │
  │  │              │            │ ()               │                  │
  │  │ ① 分配物理页  │            │                  │                  │
  │  │ ② 建页表映射  │            │ ① 红黑树找空闲   │                  │
  │  │ ③ 初始化空闲  │            │ ② 切分区域       │                  │
  │  │    红黑树     │            │ ③ 返回 buffer    │                  │
  │  └──────────────┘            └──────────────────┘                  │
  │                                                                     │
  │  一次性开辟 ~1MB~4MB               按需从已开辟区域中切分             │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
```

## 二、阶段 1：mmap 映射 — 开辟共享空间

### 1. 用户态调用

```c
// 每个使用 Binder 的进程在初始化时都会调用 mmap
// 典型大小: 1MB (由 ProcessState 管理)
void *base = mmap(NULL,                   // 由内核选择地址
                  MAP_SIZE,               // 映射大小，通常 1MB~4MB
                  PROT_READ,              // 只读映射（写通过内核 copy_from_user）
                  MAP_SHARED,             // 共享映射
                  binder_fd,              // /dev/binder 的文件描述符
                  0);                     // 偏移量
```

### 2. 内核态 binder_mmap() 完整流程

```c
static int binder_mmap(struct file *filp, struct vm_area_struct *vma)
{
    // ═══════════════════════════════════════════════════════════
    // Step 1: 基本校验
    // ═══════════════════════════════════════════════════════════
    // 检查映射大小是否合理（通常限制为 1MB ~ 4MB）
    // 检查 vma->vm_flags 是否合法
    // 一个进程只能 mmap 一次 binder 区域

    // ═══════════════════════════════════════════════════════════
    // Step 2: 记录 VMA 信息到 binder_proc
    // ═══════════════════════════════════════════════════════════
    struct binder_proc *proc = filp->private_data;  // 获取进程描述符

    // 保存用户空间虚拟地址范围的起始和结束
    proc->buffer = (void __user *)vma->vm_start;    // 映射区起始地址
    proc->buffer_size = vma->vm_end - vma->vm_start; // 映射区总大小

    // ═══════════════════════════════════════════════════════════
    // Step 3: 延迟分配物理页面（关键！不是一次性全部分配）
    // ═══════════════════════════════════════════════════════════
    //
    // 重要: 现代内核使用 vm_ops->fault 实现延迟分配
    // mmap 时只建立虚拟地址空间范围，不立即分配所有物理页
    // 当用户态实际访问某地址时，触发缺页中断再分配对应物理页
    //
    // 设置 vm_operations_struct:
    vma->vm_ops = &binder_vm_ops;
    vma->vm_private_data = proc;

    // ═══════════════════════════════════════════════════════════
    // Step 4: 初始化空闲区域管理结构
    // ═══════════════════════════════════════════════════════════

    // 创建一个覆盖整个映射区的 binder_buffer（初始时整块都是空闲的）
    struct binder_buffer *buffer;
    buffer = kzalloc(sizeof(*buffer), GFP_KERNEL);

    buffer->data = proc->buffer;                    // 指向映射区起始
    buffer->size = proc->buffer_size;               // 大小 = 整个映射区
    buffer->free = 1;                               // 标记为空闲

    // 将这块空闲区域加入空闲红黑树（按地址排序）
    rb_link_node(&buffer->rb_node, parent, p);
    rb_insert_color(&buffer->rb_node, &proc->alloc);  // proc->alloc 是红黑树根

    // 同时加入全局 binder_buffers 链表（用于调试和清理）
    list_add(&buffer->entry, &binder_buffers);
}
```

## 三、阶段 2：事务缓冲区分配 — 在已映射区域中切分

### 1. binder_alloc_buf() 完整流程

当事务需要传输数据时，在目标进程的 mmap 区域中分配缓冲区：

```c
static struct binder_buffer *binder_alloc_buf(struct binder_proc *proc,
                                               size_t data_size,
                                               size_t offsets_size,
                                               size_t extra_buffers_size,
                                               int is_async)
{
    // ═══════════════════════════════════════════════════════════
    // Step 1: 计算需要的总大小（按页面对齐）
    // ═══════════════════════════════════════════════════════════
    size_t total_size;

    // 数据部分按 8 字节对齐
    data_size = ALIGN(data_size, sizeof(void *));

    // 偏移表按 8 字节对齐
    offsets_size = ALIGN(offsets_size, sizeof(void *));

    // 额外缓冲区（用于 fd 传输等）按页面对齐
    extra_buffers_size = ALIGN(extra_buffers_size, PAGE_SIZE);

    total_size = data_size + offsets_size + extra_buffers_size;

    // ═══════════════════════════════════════════════════════════
    // Step 2: 异步事务的空间检查
    // ═══════════════════════════════════════════════════════════
    if (is_async) {
        // 异步事务有空间限制，防止一个发送方占满所有缓冲区
        if (proc->free_async_space < total_size) {
            return NULL;  // 空间不足，返回失败
        }
        proc->free_async_space -= total_size;
    }

    // ═══════════════════════════════════════════════════════════
    // Step 3: 在空闲红黑树中查找最佳匹配的空闲区域
    // ═══════════════════════════════════════════════════════════
    //
    //  proc->alloc 红黑树:
    //  ┌─────────────────────────────────────────────────┐
    //  │  按地址排序的红黑树                               │
    //  │                                                 │
    //  │         [buffer_C: 256B, free=1]                │
    //  │        /                        \               │
    //  │  [buffer_A: 128B]        [buffer_D: 512B,free=1]│
    //  │  [free=0]               /                       │
    //  │                    [buffer_E: 1024B, free=1]    │
    //  │                                                 │
    //  │  查找: 找到第一个 size >= total_size 的空闲节点    │
    //  └─────────────────────────────────────────────────┘
    //
    struct rb_node *n = proc->alloc.rb_node;
    struct binder_buffer *buffer = NULL;

    while (n) {
        struct binder_buffer *buf = rb_entry(n, struct binder_buffer, rb_node);

        if (buf->free && buf->size >= total_size) {
            // 记录候选，但继续向左查找是否有更合适的（更小的满足条件的）
            buffer = buf;
            n = n->rb_left;
        } else if (buf->free) {
            // 当前节点太小，向右查找更大的
            n = n->rb_right;
        } else {
            // 已分配的节点，根据地址决定方向
            n = n->rb_right;
        }
    }

    if (buffer == NULL)
        return NULL;  // 找不到足够的空闲区域

    // ═══════════════════════════════════════════════════════════
    // Step 4: 切分空闲区域
    // ═══════════════════════════════════════════════════════════
    //
    //  切分前:
    //  ┌────────────────────────────────────────────────────┐
    //  │  空闲区域 buffer (size = 1024B)                     │
    //  └────────────────────────────────────────────────────┘
    //
    //  切分后 (假设需要 300B):
    //  ┌────────────┬───────────────────────────────────────┐
    //  │ 已分配 300B │  新的空闲区域 724B (1024-300)          │
    //  │ (新 buffer) │  (新 binder_buffer)                   │
    //  └────────────┴───────────────────────────────────────┘
    //
    //  如果剩余空间太小（< 2 * sizeof(void*)），则不切分，整块分配
    if (buffer->size >= total_size + 2 * sizeof(void *)) {
        // 创建新的空闲 buffer 表示剩余空间
        struct binder_buffer *new_buffer;
        new_buffer = kzalloc(sizeof(*new_buffer), GFP_KERNEL);

        new_buffer->data = (void *)buffer->data + total_size;
        new_buffer->size = buffer->size - total_size;
        new_buffer->free = 1;

        // 将新空闲区域插入红黑树
        rb_link_node(&new_buffer->rb_node, ...);
        rb_insert_color(&new_buffer->rb_node, &proc->alloc);

        // 加入全局链表
        list_add(&new_buffer->entry, &binder_buffers);
    }

    // 从红黑树中移除原来的空闲节点
    rb_erase(&buffer->rb_node, &proc->alloc);

    // ═══════════════════════════════════════════════════════════
    // Step 5: 设置已分配 buffer 的属性
    // ═══════════════════════════════════════════════════════════
    buffer->free = 0;                           // 标记为已使用
    buffer->data_size = data_size;              // 数据区大小
    buffer->offsets_size = offsets_size;        // 偏移表大小
    buffer->extra_buffers_size = extra_buffers_size; // 额外缓冲区大小

    // 计算各部分在 buffer 中的偏移
    // ┌──────────────────────────────────────────────┐
    // │  data 区域  │  offsets 区域  │  extra 区域    │
    // │  (data_size)│ (offsets_size) │ (extra_size)  │
    // └──────────────────────────────────────────────┘
    //  ◄─────────── buffer->size ──────────────────►

    return buffer;
}
```

### 2. 缓冲区切分过程图解

```
═══════════════════════════════════════════════════════════════════════════════════
  缓冲区分配与回收的完整示例
═══════════════════════════════════════════════════════════════════════════════════

  初始状态 (mmap 后):
  ┌──────────────────────────────────────────────────────────────────────────┐
  │  整个 mmap 区域 = 1 个空闲 buffer                                        │
  │  ┌────────────────────────────────────────────────────────────────────┐  │
  │  │  buffer_0: size=1MB, free=1                                       │  │
  │  └────────────────────────────────────────────────────────────────────┘  │
  │                                                                          │
  │  红黑树: { buffer_0(1MB, free) }                                         │
```

## 四、缓冲区释放与合并

### 1. binder_free_buf() — 释放缓冲区

```c
static void binder_free_buf(struct binder_proc *proc,
                             struct binder_buffer *buffer)
{
    // 标记为空闲
    buffer->free = 1;
    buffer->data_size = 0;
    buffer->offsets_size = 0;

    // 重新插入空闲红黑树
    rb_link_node(&buffer->rb_node, parent, p);
    rb_insert_color(&buffer->rb_node, &proc->alloc);

    // 异步事务空间回收
    if (buffer->is_async) {
        proc->free_async_space += buffer_size;
    }

    // 尝试与相邻空闲区域合并
    binder_free_buf_locked(proc, buffer);
}
```

### 2. 相邻空闲区域合并

```
═══════════════════════════════════════════════════════════════════════════════════
  合并过程
═══════════════════════════════════════════════════════════════════════════════════

  释放前:
  ┌──────────────┬──────────────┬──────────────┬──────────────┐
  │ 空闲 200KB   │ 已分配 300KB │ 空闲 548KB   │ 已分配 100KB │
  │ buffer_A     │ buffer_B     │ buffer_C     │ buffer_D     │
  │ free=1       │ free=0       │ free=1       │ free=0       │
  └──────────────┴──────────────┴──────────────┴──────────────┘

  释放 buffer_B 后:
  ┌──────────────┬──────────────┬──────────────┬──────────────┐
  │ 空闲 200KB   │ 空闲 300KB   │ 空闲 548KB   │ 已分配 100KB │
  │ buffer_A     │ buffer_B     │ buffer_C     │ buffer_D     │
  │ free=1       │ free=1(刚释放)│ free=1       │ free=0       │
  └──────────────┴──────────────┴──────────────┴──────────────┘
       ▲               ▲               ▲
       │               │               │
       └── 左邻空闲 ───┘─── 右邻空闲 ───┘

  合并步骤:
  1. 检查左邻 (buffer_A): free=1 → 可以合并!
     buffer_A.size += buffer_B.size  (200KB + 300KB = 500KB)
     从红黑树中移除 buffer_B

  2. 检查右邻 (buffer_C): free=1 → 可以合并!
     buffer_A.size += buffer_C.size  (500KB + 548KB = 1048KB)
     从红黑树中移除 buffer_C

  合并后:
  ┌─────────────────────────────────────────────┬──────────────┐
  │ 空闲 1048KB                                  │ 已分配 100KB │
  │ buffer_A (合并后)                             │ buffer_D     │
  │ free=1                                       │ free=0       │
  └─────────────────────────────────────────────┴──────────────┘

  红黑树: { buffer_A(1048KB, free), buffer_D(已分配) }
```

## 六、总结：映射与开辟的关键设计

| 设计要点 | 实现方式 | 目的 |
|---------|---------|------|
| **一次性预留地址空间** | `mmap()` 建立虚拟地址范围 | 确定 Binder 通信的内存边界 |
| **延迟分配物理页** | `vm_ops->fault` 缺页中断 | 按需分配，不浪费未使用的物理内存 |
| **物理页共享** | 同一物理页同时映射到用户空间和内核空间 | 实现一次拷贝的核心基础 |
| **红黑树管理空闲区域** | `proc->alloc` 红黑树按地址排序 | O(log n) 高效查找和分配空闲缓冲区 |
| **相邻空闲合并** | 释放时检查左右邻居并合并 | 避免内存碎片化 |
| **异步空间限制** | `free_async_space` 独立计数 | 防止异步事务占满所有缓冲区 |
| **按页释放** | `proc->pages[]` 数组记录所有物理页 | 进程退出时快速回收所有物理页 |
