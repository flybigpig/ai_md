# Binder 红黑树机制详解

---

## 一、红黑树在 Binder 中的使用总览

Binder 驱动中大量使用红黑树（`struct rb_root` + `struct rb_node`）来高效管理各种内核对象。共有 **5 棵关键红黑树**：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        binder_proc 中的红黑树                               │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  proc->nodes                                                        │   │
│  │  作用: 管理本进程发布的所有 binder_node（服务端）                       │   │
│  │  排序键: ptr（用户态 binder 对象指针）                                │   │
│  │  操作: 查找服务、注册服务、释放服务                                    │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  proc->refs                                                         │   │
│  │  作用: 管理本进程持有的所有 binder_ref（按 node 指针排序）              │   │
│  │  排序键: node（指向的 binder_node 地址）                              │   │
│  │  操作: 根据 node 查找 ref、增加/减少引用                              │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  proc->refs_by_desc                                                 │   │
│  │  作用: 管理本进程持有的所有 binder_ref（按 handle/desc 排序）          │   │
│  │  排序键: desc（用户态 handle 值）                                     │   │
│  │  操作: 根据 handle 查找 ref（事务路由的核心！）                         │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  proc->threads                                                      │   │
│  │  作用: 管理本进程的所有 binder 线程                                    │   │
│  │  排序键: pid（线程 PID）                                             │   │
│  │  操作: 查找线程、清理线程                                             │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  proc->alloc                                                        │   │
│  │  作用: 管理 mmap 映射区域的缓冲区分配（空闲+已分配）                    │   │
│  │  排序键: data（缓冲区在映射区中的地址偏移）                             │   │
│  │  操作: 分配缓冲区、释放缓冲区、合并空闲块                               │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、为什么选择红黑树

```
═══════════════════════════════════════════════════════════════════════════════════
  数据结构选型对比
═══════════════════════════════════════════════════════════════════════════════════

  ┌──────────────────┬──────────┬──────────┬──────────┬──────────────┐
  │ 数据结构          │ 查找     │ 插入     │ 删除     │ 适用场景      │
  ├──────────────────┼──────────┼──────────┼──────────┼──────────────┤
  │ 链表 (list_head) │ O(n)     │ O(1)     │ O(1)     │ 频繁遍历      │
  │ 数组             │ O(1)     │ O(n)     │ O(n)     │ 固定大小      │
  │ 哈希表           │ O(1)平均 │ O(1)     │ O(1)     │ 等值查找      │
  │ 红黑树 (rb_root) │ O(log n) │ O(log n) │ O(log n) │ 范围/排序查找 │
  └──────────────────┴──────────┴──────────┴──────────┴──────────────┘

  Binder 选择红黑树的原因:
  ┌─────────────────────────────────────────────────────────────────────────┐
  │                                                                         │
  │  1. 需要按 key 排序/范围查找                                             │
  │     → refs_by_desc 需要按 handle 值排序                                  │
  │     → alloc 需要按地址排序，支持相邻块合并                                │
  │                                                                         │
  │  2. 需要稳定的 O(log n) 性能                                             │
  │     → Binder 是系统关键路径，不能有哈希冲突导致的性能抖动                  │
  │     → 红黑树保证最坏情况也是 O(log n)                                    │
  │                                                                         │
  │  3. 内核已有成熟的红黑树实现                                              │
  │     → Linux 内核提供 rbtree.h，接口完善                                  │
  │     → 无需额外内存分配（rb_node 内嵌在对象中）                             │
  │                                                                         │
  │  4. 并发安全                                                             │
  │     → 配合 spinlock 可以安全地在多线程环境下操作                           │
  │                                                                         │
  └─────────────────────────────────────────────────────────────────────────┘
```

## 三、proc->refs_by_desc — 事务路由的核心

这是 Binder 事务传输中最关键的一棵红黑树，每次 IPC 调用都要通过它查找目标服务。

### 1. 数据结构

```c
// binder_ref 中嵌入两个 rb_node，分别挂到两棵红黑树
struct binder_ref {
    struct rb_node rb_node_desc;      // 挂在 proc->refs_by_desc（按 handle 排序）
    struct rb_node rb_node_node;      // 挂在 proc->refs（按 node 指针排序）
    u32 desc;                         // handle 值（排序键）
    struct binder_node *node;         // 指向的 binder_node
    // ...
};
```

### 2. 红黑树结构详解

```
═══════════════════════════════════════════════════════════════════════════════════
  proc->refs_by_desc 红黑树 — 按 handle(desc) 值排序
═══════════════════════════════════════════════════════════════════════════════════

  假设进程 A 持有以下远程服务引用:
  ┌──────────────────────────────────────────────────────┐
  │  binder_ref: desc=0  → ServiceManager               │
  │  binder_ref: desc=3  → ActivityManager              │
  │  binder_ref: desc=5  → PackageManager               │
  │  binder_ref: desc=7  → WindowManager                │
  │  binder_ref: desc=12 → NotificationManager          │
  └──────────────────────────────────────────────────────┘

  对应的红黑树:
  ┌─────────────────────────────────────────────────────────────────────┐
  │                                                                     │
  │                    ┌──────────────┐                                 │
  │                    │ desc=5 (B)   │  ← 根节点（黑色）                │
  │                    │ (PkgMgr)     │                                 │
  │                    └──────┬───────┘                                 │
  │                           │                                         │
  │              ┌────────────┴────────────┐                            │
  │              │                         │                            │
  │     ┌────────▼───────┐       ┌────────▼───────┐                   │
  │     │ desc=3 (R)     │       │ desc=12 (R)    │  ← 红色节点        │
  │     │ (ActMgr)       │       │ (NotifMgr)     │                   │
  │     └───────┬────────┘       └────────────────┘                   │
  │             │                                                      │
  │        ┌────┴────┐                                                 │
  │        │         │                                                 │
  │  ┌─────▼───┐ ┌───▼──────┐                                         │
  │  │desc=0(B)│ │desc=7(B) │  ← 黑色节点                             │
  │  │(SvcMgr) │ │(WinMgr)  │                                         │
  │  └─────────┘ └──────────┘                                         │
  │                                                                     │
  │  中序遍历: 0 → 3 → 5 → 7 → 12  (有序!)                             │
  │                                                                     │
  │  查找 desc=7:                                                      │
  │    根 5 < 7 → 走右子树                                              │
  │    节点 12 > 7 → 走左子树                                           │
  │    节点 7 == 7 → 找到!  O(log n) = 3 次比较                         │
  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
```

### 3. 查找过程（事务路由）

```c
// 当 Client 发起事务时，通过 handle 查找 binder_ref
static struct binder_ref *binder_get_ref(struct binder_proc *proc,
                                          u32 desc, bool do_lock)
{
    struct rb_node *n = proc->refs_by_desc.rb_node;
    //          ↑ 从红黑树根节点开始

    while (n) {
        struct binder_ref *ref = rb_entry(n, struct binder_ref, rb_node_desc);
        //                ↑ 通过 rb_entry 宏从 rb_node 获取外层 binder_ref

        if (desc < ref->desc) {
            // handle 值小于当前节点 → 走左子树
            n = n->rb_left;
        } else if (desc > ref->desc) {
            // handle 值大于当前节点 → 走右子树
            n = n->rb_right;
        } else {
            // 找到了! 返回 binder_ref
            return ref;
        }
    }
    // 未找到 → 无效 handle
    return NULL;
}
```

```
  │                  └────────────────┘                                 │
  │                                                                     │
  │  Step 2: 通过 ref->node 找到目标 binder_node                       │
  │          target_proc = ref->node->proc  → WindowManager 所在进程    │
  │                                                                     │

  │                                                                     │
  └─────────────────────────────────────────────────────────────────────┘
```

### 4. 插入过程

```c
// 当 Client 获取新服务引用时，将 binder_ref 插入红黑树
static int binder_get_ref_for_node(struct binder_proc *proc,
                                    struct binder_node *node,
                                    struct binder_ref **return_ref)
{
    struct rb_node **p = &proc->refs_by_desc.rb_node;  // 指向根节点指针
    struct rb_node *parent = NULL;
    struct binder_ref *new_ref;

    // 分配新的 binder_ref
    new_ref = kzalloc(sizeof(*new_ref), GFP_KERNEL);
    new_ref->node = node;

    // ═══════════════════════════════════════════════════════
    // 查找插入位置（BST 插入）
    // ═══════════════════════════════════════════════════════
    while (*p) {
        struct binder_ref *ref;
        parent = *p;
        ref = rb_entry(parent, struct binder_ref, rb_node_desc);

        if (new_ref->desc < ref->desc) {
            p = &(*p)->rb_left;      // 向左走
        } else if (new_ref->desc > ref->desc) {
            p = &(*p)->rb_right;     // 向右走
        } else {
            // desc 已存在，不应发生
            kfree(new_ref);
            return -1;
        }
    }

    // ═══════════════════════════════════════════════════════
    // 插入节点 + 红黑树平衡
    // ═══════════════════════════════════════════════════════
    rb_link_node(&new_ref->rb_node_desc, parent, p);
    //  ↑ 将新节点链接到 parent 的左/右孩子位置

    rb_insert_color(&new_ref->rb_node_desc, &proc->refs_by_desc);
    //  ↑ 执行红黑树旋转/着色，恢复红黑树性质
    //    内部可能执行:
    //    - 左旋 (rotate_left)
    //    - 右旋 (rotate_right)
    //    - 颜色翻转 (recolor)

    // 同时插入 proc->refs 红黑树（按 node 指针排序）
    // ... 类似过程 ...
}
```

### 5. 删除过程

```c
// 当释放引用时，从红黑树中删除 binder_ref
static void binder_delete_ref(struct rb_root *root, struct binder_ref *ref)
{
    // 从 refs_by_desc 红黑树中删除
    rb_erase(&ref->rb_node_desc, root);
    //  ↑ 内部执行:
    //    1. 找到替代节点（后继或前驱）
    //    2. 替换被删除节点
    //    3. 旋转/变色恢复红黑树性质

    // 同时从 refs 红黑树中删除
    rb_erase(&ref->rb_node_node, &ref->proc->refs);
}
```

## 四、proc->alloc — 缓冲区管理的红黑树

这棵红黑树管理 mmap 映射区域内的所有缓冲区（空闲 + 已分配）。

### 1. 结构特点

```
═══════════════════════════════════════════════════════════════════════════════════
  proc->alloc 红黑树 — 按缓冲区地址排序
═══════════════════════════════════════════════════════════════════════════════════

  mmap 映射区域 (假设 1MB):
  ┌──────────────────────────────────────────────────────────────────────────┐

  │  │ free=0   │ free=0   │ free=0   │ free=1       │ free=1           │   │
  │  └──────────┴──────────┴──────────┴──────────────┴──────────────────┘   │
  │  ↑ 0x7F00_0000    ↑ 0x7F00_0080   ↑ 0x7F00_0180  ↑ 0x7F00_01C0        │
```

### 2. 分配时的查找过程

```c
// 在 alloc 红黑树中查找足够大的空闲区域
static struct binder_buffer *binder_alloc_buf(struct binder_proc *proc,
                                               size_t size, ...)
{
    struct rb_node *n = proc->alloc.rb_node;
    struct binder_buffer *buffer = NULL;
    struct binder_buffer *best_fit = NULL;

    while (n) {
        struct binder_buffer *buf = rb_entry(n, struct binder_buffer, rb_node);

        if (buf->free) {
            if (buf->size >= size) {
                // 当前空闲块够大 → 记录为候选
                best_fit = buf;
                // 继续向左查找是否有更小的满足条件的块（最佳适配）
                n = n->rb_left;
            } else {
                // 当前空闲块太小 → 向右查找更大的
                n = n->rb_right;
            }
        } else {
            // 已分配的块 → 根据地址决定方向
            // 实际上需要遍历，这里简化
            n = n->rb_right;
        }
    }

    return best_fit;  // 返回最佳匹配的空闲块（可能为 NULL）
}
```

## 八、红黑树操作的内核接口

```c
// ═══════════════════════════════════════════════════════════════════
// Linux 内核红黑树 API (include/linux/rbtree.h)
// ═══════════════════════════════════════════════════════════════════

// 初始化
struct rb_root root = RB_ROOT;    // 空树

// 查找 (手动遍历)
struct rb_node *n = root.rb_node;
while (n) {
    struct my_struct *obj = rb_entry(n, struct my_struct, rb_node);
    if (key < obj->key)
        n = n->rb_left;
    else if (key > obj->key)
        n = n->rb_right;
    else
        return obj;  // 找到
}

// 插入
rb_link_node(&new_obj->rb_node, parent, insert_point);
rb_insert_color(&new_obj->rb_node, &root);  // 自动平衡

// 删除
rb_erase(&obj->rb_node, &root);             // 自动平衡

// 遍历 (中序)
struct rb_node *n;
for (n = rb_first(&root); n; n = rb_next(n)) {
    struct my_struct *obj = rb_entry(n, struct my_struct, rb_node);
    // 按 key 递增顺序处理
}

// 关键宏
// rb_entry(ptr, type, member)  — 从 rb_node 指针获取外层结构体指针
// rb_first(root)               — 获取最小节点
// rb_last(root)                — 获取最大节点
// rb_next(node)                — 获取中序后继
// rb_prev(node)                — 获取中序前驱
```

## 九、总结

| 红黑树 | 排序键 | 核心用途 | 操作频率 |
|--------|--------|---------|---------|
| **refs_by_desc** | handle (desc) | 事务路由：根据用户态 handle 查找目标服务 | 每次 IPC 调用 |
| **refs** | node 指针 | 引用管理：按 node 查找 ref，引用计数操作 | 每次获取/释放引用 |
| **nodes** | ptr (用户态指针) | 服务管理：注册/查找/释放服务节点 | 服务注册时 |
| **threads** | pid | 线程管理：查找/清理 binder 线程 | 线程创建/退出 |
| **alloc** | data 地址 | 缓冲区管理：分配/释放/合并 mmap 区域中的缓冲区 | 每次事务 |

红黑树是 Binder 驱动高效运转的基石 — 所有关键路径上的查找操作都保证 **O(log n)** 时间复杂度，使得 Android 系统即使在高并发场景下也能维持稳定的 IPC 性能。
