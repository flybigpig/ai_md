⑤ 烧录（SP Flash Tool）

  • scatter 用本次编译生成的 MT6893_Android_scatter.txt。
  • Secure Boot：量产机必须加载 auth_sv.bin / da_auth（SP Flash Tool → Auth 选项卡），否则 BROM ERROR: STATUS_SEC_IMG_NOT_FOUND。
  • 下载项：勾选 preloader, lk, gz, boot, vendor_boot, dtbo, vbmeta*, super, md1img, tee, spmfw, mcupm, scp, sspm, logo 等（scatter 默认全选即可）。
  • 关机插 USB 触发 BROM → 自动加载 DA → 绿色 ✓。

⑧ Android 14 专属坑

  1. JDK 必须是 17，否则 lunch 直接挂。
  2. GKI：boot.img 与 vendor_boot.img 分离，老习惯只烧 boot 会卡内核。
  3. 动态分区：别单独烧 system/vendor/product，烧 super.img；fastboot flash system 在动态分区上要用 fastboot flash super 或 fastboot update。
  4. AVB：vbmeta 没烧或 key 不匹配 → 红字 vbmeta 校验失败，需 fastboot --disable-verification 或烧正确 vbmeta。
  5. 16KB 页（可选）：Android 14 起支持 16KB page，但 MT6893 仍用 4KB，别误开 BOARD_KERNEL_PAGESIZE=16384。
  6. 内存：Android 14 全编比 11/12 更吃内存，强烈建议 32GB+，否则 m 中途 OOM。

平台对齐注记（WorkBuddy 补充，不改原文）

与本系列文档的关系：本文是第 4 份《MTK 编译烧录实操手册（通用）》的 MT6893 + Android 14 精确版。相对通用版的关键增量：

  • GKI 分离：boot.img（GKI kernel + generic ramdisk）与 vendor_boot.img（DTB + vendor ramdisk）拆开，DTB 不再在 boot.img。这是 Android 12+ 强制，本文的"三者同烧"是 Android 14 的硬约束。
  • 动态分区：system/vendor/product/system_ext/odm 合并为 super.img；scatter 里这些子分区通常 is_download:false 或不存在，只烧 super。
  • AVB2：vbmeta 拆成 img / system / vendor 三张，校验粒度更细；量产机不开 --disable-verification 基本起不来。
  • JDK17 + Ubuntu 22.04：与通用版（Android 11/12 用 JDK11）形成明确分界。

仍需以你 BSP 为准的点：

  • kernel-5.15/ 是 MTK Android 14 BSP 的典型内核目录名，但最终以你解压后的真实目录名为准（可能 backport 到 5.10 或 6.1）。
  • gz 分区的语义在不同 release 有差异（EL3 辅助 vs 纯安全小镜像），以 Release Note 描述为准。
