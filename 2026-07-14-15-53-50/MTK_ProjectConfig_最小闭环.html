MTK 定制最小闭环：改一个 ProjectConfig 开关并验证

以 MT6765 + Android 11（eng）为例 · 宏 → 模块 → 编译 → 烧录/推送 → 验证 全链路 · 助理补充文档

本文是 MTK 知识文档集的第 5 份，作为用户「开发指南」第 ⑦ 节子项的实操展开。示例平台 MT6765 + Android 11（你对照表里"最常见低端 PDA"组合）；若你的机器是 MT6893/天玑或别的 Android 版本，只需替换 platform 名与 JDK/内核，流程不变。路径以通用 BSP 为准，务必对照你的 Release Note。

0. 为什么选这个开关

我们要挑一个改动安全、结果可观察、且能体现"宏如何流向编译"的开关。选 MTK_ENGINEER_MODE_SUPPORT：

  • 它控制 EngineerMode 工程 App（com.mediatek.engineermode）是否被编入并预装；
  • 开/关后 adb shell pm list packages 立刻可见差异，无需看画面；
  • 不涉及内核/驱动，不会变砖，适合"第一次"。

完整链路如下：

graph LR A["ProjectConfig.mk
MTK_ENGINEER_MODE_SUPPORT=yes"] --> B["device.mk / *.mk
ifneq 包裹 PRODUCT_PACKAGES += EngineerMode"] B --> C["packages/apps/EngineerMode/
Android.mk (LOCAL_MODULE)"] C --> D["编译产出
out/.../system/priv-app/EngineerMode"] D --> E["烧录/推送 system(super)"] E --> F["验证: pm list packages
grep engineer"]

1. 找到开关

# 路径（MT6765）
device/mediatek/mt6765/ProjectConfig.mk
# 搜索
grep -n "MTK_ENGINEER_MODE_SUPPORT" device/mediatek/mt6765/ProjectConfig.mk
# 典型内容
MTK_ENGINEER_MODE_SUPPORT = yes
注意：MTK 会把 ProjectConfig.mk 的宏"翻译"成 device/mediatek/mt6765/ProjectConfig.mk 里的最终值，部分 release 还会有一层 vendor/mediatek/proprietary/build/... 生成的 alps_release_*.mk。以 device/mediatek/<platform>/ProjectConfig.mk 里你实际编辑的那份为准。

2. 看它怎么被"消费"（关键：宏 → 模块）

MTK 的宏不会自动生效，必须在某个 .mk 里被 ifneq/ifdef 引用才会影响编译。EngineerMode 的引用通常在平台 device.mk 或其 include 链上：

# 常见位置之一：device/mediatek/mt6765/device.mk 或
# device/mediatek/common/device.mk（被 platform device.mk inherit）
ifneq ($(strip $(MTK_ENGINEER_MODE_SUPPORT)),no)
  PRODUCT_PACKAGES += EngineerMode
endif

而 App 自身的 Android.mk 只声明模块名，不判宏：

# packages/apps/EngineerMode/Android.mk（节选）
LOCAL_PATH := $(call my-dir)
include $(CLEAR_VARS)
LOCAL_MODULE := EngineerMode
LOCAL_MODULE_TAGS := optional
LOCAL_PRIVILEGED_MODULE := true
LOCAL_CERTIFICATE := platform
include $(BUILD_PACKAGE)
链路小结（这就是"宏如何变成 APK"）：
ProjectConfig.mk 的 MTK_ENGINEER_MODE_SUPPORT=yes
→ 被 device.mk 的 ifneq 捕获 → PRODUCT_PACKAGES += EngineerMode
→ 打包系统把 packages/apps/EngineerMode 编进 system（priv-app）
→ 烧录后 /system/priv-app/EngineerMode/EngineerMode.apk 存在。

3. 改开关

把 MTK_ENGINEER_MODE_SUPPORT 从 yes 改成 no（或反过来），保存。

# 仅演示"关掉"，看 App 是否消失
MTK_ENGINEER_MODE_SUPPORT = no
安全点：只动这一个宏，不碰其他 MTK_*；这是非破坏性修改，最坏结果是少个工程 App。

4. 最小重编

坑预警：ProjectConfig.mk 的改动有时不会自动触发，因为 MTK 会在 out/ 里缓存生成的 ProjectConfig / featureoption。两种可靠做法：

# 做法 A（推荐，干净）：MTK 自带 mk 重编
cd alps
./mk mt6765 r          # remake，会重新解析 ProjectConfig

# 做法 B（只想重编 App 模块，快但不一定重解析宏）：
source build/envsetup.sh && lunch mt6765-eng
mmm packages/apps/EngineerMode/     # 仅重编该 APK
# 注意：若 B 没生效（宏没被重读），回到 A
经验法则：凡是改了 ProjectConfig.mk 的新增/删除 PRODUCT_PACKAGES，用 ./mk <platform> r 最稳；只改 App 内部代码才用 mmm。

5. 烧录 / 推送

MT6765 + Android 11 大概率是动态分区（super.img）。两种落地方式：

方式命令适用
整包烧录（最稳）SP Flash Tool 加载本次 MT6765_Android_scatter.txt，勾选 super + boot + vbmeta 等，Download所有情况
eng 版免烧录（快）adb root && adb remount && adb sync system 或 adb push out/.../EngineerMode.apk /system/priv-app/EngineerMode/仅 eng build，且未锁
# eng 快速验证路径（推荐先走这条，省去烧录）
adb root
adb remount
adb sync system          # 把 out/ 里 system 变更同步到设备
adb reboot

6. 验证（看结果）

# 开关=yes 时应能看到：
adb shell pm list packages | grep -i engineer
# → package:com.mediatek.engineermode

# 开关=no 后应看不到（或仅残留 data 区，需恢复出厂/清 data）：
adb shell pm list packages | grep -i engineer
# → 无输出

# 顺带确认宏是否进系统属性（很多 MTK_* 会映射成 ro.mtk_*）
adb shell getprop | grep -i mtk | grep -i engineer
闭环完成：改一个宏 → 重编 → 设备上的包列表随之变化。这就是 MTK 定制最基础的"可观测最小回路"。

7. 进阶：自定义一个 MTK_* 宏控制你自己的 App

想让你自己的 PDA 应用随宏预装/剔除，照葫芦画瓢：

# 1) device/mediatek/mt6765/ProjectConfig.mk 末尾加
MTK_MY_PDA_FEATURE = yes

# 2) device/mediatek/mt6765/device.mk 加
ifneq ($(strip $(MTK_MY_PDA_FEATURE)),no)
  PRODUCT_PACKAGES += MyPdaApp
endif

# 3) packages/apps/MyPdaApp/Android.mk 里
LOCAL_MODULE := MyPdaApp
#   （正常 BUILD_PACKAGE）

# 4) ./mk mt6765 r  → 验证 pm list packages | grep MyPdaApp

8. 常见坑

  1. 改了宏没反应：out/ 缓存了旧的 ProjectConfig，用 ./mk <platform> r 或删 out/target/product/<platform>/obj/ 下对应缓存后再编。
  2. user 版不能 remount：adb remount 失败 → 改用 SP Flash Tool 烧 super.img，或改用 userdebug/eng。
  3. 动态分区烧错：改了 system 内容却只烧 system.img 而设备是 super → 不生效；务必烧 super.img。
  4. 宏名拼错：MTK_ENGINEER_MODE_SUPPORT 大小写敏感，ifneq 比对的是字符串，写错即恒等不匹配。
