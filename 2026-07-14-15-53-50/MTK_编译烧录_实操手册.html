① 主机环境

项建议
系统Ubuntu 18.04 / 20.04 / 22.04（按 Android 版本选，见末尾表）
内存≥ 32GB（MTK 全编非常大，16GB 容易 OOM）
磁盘≥ 500GB SSD（源码 + out/ 轻松占 300GB+）
CPU多核越多越快（建议 16 核+）

安装编译依赖（Ubuntu 20.04 示例）：

sudo apt update

  xsltproc unzip python3 python3-pip gcc-multilib g++-multilib \
  libssl-dev lib32stdc++6

JDK（按 Android 版本，关键！）：

# Android 9/10  → OpenJDK 8
sudo apt install openjdk-8-jdk
# Android 11/12 → OpenJDK 11
sudo apt install openjdk-11-jdk
# Android 13/14 → OpenJDK 17
sudo apt install openjdk-17-jdk

配置默认 JDK：sudo update-alternatives --config java

repo 工具：

mkdir -p ~/bin && curl https://storage.googleapis.com/git-repo-downloads/repo > ~/bin/repo
chmod +x ~/bin/repo && export PATH=~/bin:$PATH

② 获取源码（MTK 特有，不是 AOSP）

MTK 源码不在公开 AOSP，来自 MTK Partner Portal（https://online.mediatek.com ，需授权账号 + NDA）。典型交付物：

alps-release-<version>-<chip>-<date>.tar.gz   # 主框架（分卷 alps-*.tar.gz.aa/.ab...）
kernel-<ver>-<chip>.tar.gz                     # 内核
vendor-mediatek-proprietary-<chip>.tar.gz      # 闭源 BSP（最大，常单独给）

拿到后合并解压：

cat alps-*.tar.gz.* | tar -xzvf -        # 分卷合并解压
tar -xzf kernel-4.19-mt6765.tar.gz
tar -xzf vendor-mediatek-proprietary.tar.gz
⚠️ 最常见的新手坑：vendor/mediatek/proprietary/ 没解压到位 → 编译时 HAL 全找不到。解压后务必确认 vendor/mediatek/proprietary/hardware/ 有内容。

③ 编译

cd alps            # 你的源码根目录
source build/envsetup.sh

# lunch 目标格式：<platform>-<variant>
#   variant: eng(开发/root) / userdebug(接近量产可调试) / user(量产)
lunch mt6765-userdebug
# 或 MT6893:
lunch mt6893-eng

# 方式 A：标准 AOSP make（推荐，可控）
make -j$(nproc) 2>&1 | tee build.log

# 方式 B：MTK 自带 mk 脚本（部分 BSP 推荐）
./mk mt6765 n        # new，全编
./mk mt6765 r        # remake
./mk mt6765 r pl lk  # 只重编 preloader + lk

编译产物（关键文件，烧录用）

out/target/product/mt6765/
├── MT6765_Android_scatter.txt     # ★ scatter 分区表（烧录必需）

└── userdata.img

④ 烧录（SP Flash Tool）

MTK 烧录用 SP Flash Tool（Windows 为主，也有 Linux 版）。

前置（Windows）：

  1. 装 MTK VCOM 驱动（MTK_All_In_One_DA_USB_Driver / MTK USB Port）。
  2. 下载 SP Flash Tool（如 SP_Flash_Tool_v5.xx）。
sequenceDiagram participant PC as SP Flash Tool (Win) participant DEV as MTK 设备(关机) PC->>PC: 选 Download 模式 PC->>PC: 加载 scatter.txt PC->>PC: 勾选要烧的分区(默认全选) PC->>PC: 点 "Download" PC->>DEV: 提示插入设备 → 关机连 USB Note over DEV: 触发 BROM( preloader ) 模式
自动握手 DA DEV->>PC: 开始下载各 img PC->>PC: 显示绿色 ✓ Download OK PC->>DEV: 断开, 开机

要点：

  • 进 download 模式：关机状态下插 USB（部分机型需先拔电池/不插电池），工具会自动走 BROM → 加载 DA。
  • Secure Boot 设备：必须加载 auth_sv.bin / da_auth 授权文件（在 SP Flash Tool 的 "Auth" 选项卡），否则报 SECURE BOOT: DL image not signed 或 BROM ERROR: STATUS_SEC_IMG_NOT_FOUND。
  • scatter 必须匹配：用本次编译生成的 scatter，不能用别的机型/版本的，否则分区错位变砖。

替代：Fastboot（需解锁）

adb reboot bootloader
fastboot flash boot boot.img
fastboot flash vendor vendor.img
fastboot reboot
MTK 很多量产机 bootloader 锁死，Fastboot 不可用，只能走 SP Flash Tool。

⑦ 新手最常踩的坑

  1. vendor/mediatek/proprietary 没解压 → HAL 编译失败。先确认目录非空。
  2. JDK 版本错 → lunch 或 make 直接报 Unsupported class file major version。
  3. 内存不够 → make 中途 OOM 被杀，建议加 export USE_CCACHE=1 并设大 ccache，或减 -j 线程数。
  4. Secure Boot 没加 auth 文件 → 烧录报安全错误。量产机几乎都开了。
  5. scatter 版本不匹配 → 分区错位，轻则起不来，重则变砖（需 BROM 强刷）。
  6. Python 版本：老 BSP（Android 9 及更早）脚本可能要 python 指向 python2；新版要 python3，用 update-alternatives 切。
  7. 动态分区（Android 10+）：system/vendor/product 合并成 super.img，SP Flash Tool 里烧 super 而不是单独烧三个。
〔助理注，不改原文〕
  • 对你 ERP PDA 的落点：你表里点名 MT6765 是"最常见低端 PDA"——若你的 PDA 正是 MT6765，这份手册的环境/编译/烧录步骤可直接套用（Android 11 配 Ubuntu 20.04 + JDK11 最稳）。但作为 App 开发，你不需要自己编全系统；产线/FAE 编好整包后你拿 out/ 里的 system.img/super.img 烧录验证即可。
  • 动态分区实操提醒：Android 10+ 烧 super.img 时，SP Flash Tool 的 scatter 里 super 分区通常标记 is_download: true 且含 linear_size，不要手工去改 system/vendor/product 三个老分区的偏移，否则与 super 冲突。
  • BROM 强刷 vs 普通 Download：普通 Download 走 preloader→DA；"变砖"后若 preloader 也坏了，需要真正的 BROM 模式（强制进 BL 阶段握手），这对应你下一个可选主题"变砖后 BROM 强刷救机"。
