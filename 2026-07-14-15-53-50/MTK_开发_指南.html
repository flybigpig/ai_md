本文由用户撰写，按实际工程视角拆分 MTK Android 平台开发。MTK 源码来自 partner 门户（alps-release-*），非公开 AOSP；命令/路径随芯片（MT67xx / MT68xx / 天玑）与 Android 版本会变化。

你之前的 ERP PDA 是 App 层，基本不碰下面三层；但如果 PDA 是 MTK 平台，产线烧录/校准就会用到下面工具。

1. 编译与打包

MTK 源码不走公开 AOSP，来自 MTK partner 门户（alps-release-* 包），编译框架沿用 AOSP 但多了 MTK 自己的 mk 工具。

# 标准 AOSP 流程（MTK 同样适用）
source build/envsetup.sh
lunch mt68xx-eng          # 或 mt6765-userdebug
make -j$(nproc)

# 单模块编译（最常用）
mmm vendor/mediatek/proprietary/hardware/mtkcam/
mmm frameworks/base/      # 改了 framework 后重编

# MTK 自有打包脚本（生成可烧录镜像）
# vendor/mediatek/proprietary/build/ 下的 mk 工具
./mk mt68xx n            # new build
./mk mt68xx r pl lk      # 只重编 preloader + lk

关键配置文件

  • device/mediatek/mt68xx/ProjectConfig.mk — MTK 功能总开关，几千个 MTK_* 宏（MTK_CAMERA_APP、MTK_GMO_RAM_OPTIMIZE、MTK_TC1_FEATURE…），定制几乎都从这里改。
  • device/mediatek/mt68xx/device.mk — 模块/包选择。
  • vendor/mediatek/proprietary/trustzone/ 与 scripts/sign-image/ — 签名。

2. 烧录工具链（最核心的"开发外设"）

graph LR PC["PC 端工具"] -->|USB VCOM| DEV["MTK 设备(Download 模式)"] PC --> SF["SP Flash Tool
(scatter 烧录)"] PC --> SM["SP Meta Tool
(RF/ sensor 校准)"] PC --> SN["SN Writer
(IMEI/SN 写号)"] SF -->|DA 握手| DEV
  • SP Flash Tool：基于 MT68xx_Android_scatter.txt（scatter 文件，描述各分区偏移/大小）烧录。进入 download 模式：关机后 USB 拔插触发 VCOM，或特定组合键。
  • Download Agent (DA)：DA_SWSEC.bin / DA_PL.bin，preloader 阶段握手用的小程序。
  • SP Meta Tool：工厂校准（RF、camera sensor、touch、电池）。
  • SN Writer / WWR：写 IMEI、SN、MAC。

常见分区（scatter 里能看到）

preloader, lk, boot, recovery, vbmeta, system, vendor, product, userdata, md1img(modem), spmfw, mcupm, scp, sspm, tee, nvdata, nvram, protect1/2, para, logo, expdb, frp, metadata

3. 调试 / 日志体系（MTK 特色）

MTK 的日志比原生 AOSP 多一套 AEE + mtklogger 体系：

工具 / 路径用途
/data/aee_exp/ , /sdcard/mtklog/AEE 崩溃 dump（KE/HW/NE/JE/SWT）
mtklogger App（vendor/.../apps/MTKLogger）一键抓取 kernel+android+modem 日志
GAT（桌面端）实时抓取 + 解析 mtklog
MTK Catcher / ELTModem（MD）层日志，分析掉网/通话
dmesg / /proc/kmsg内核日志
expdb 分区存放异常数据库，配合 aee 解析
调试 MTK 设备第一件事通常是先开 mtklogger 抓一份全日志，再拿 AEE 的 db 文件用 GAT 解析。

5. 安全启动 / 签名

  • Secure Boot：MTK 用 da_auth / auth_sv 授权文件 + vbmeta(AVB) 或自有 sec 签名。
  • 签名脚本：vendor/mediatek/proprietary/scripts/sign-image/sign.py（对 boot/recovery/preloader 签名）。
  • 未授权 DA 无法烧录开启了 Secure Boot 的设备——这是产线防刷机的关键。

〔助理注，不改原文〕
  • 关于你的 ERP PDA 定位：如文中所说 PDA 属 App 层，正常开发不碰 BSP/Framework/产线。但有两个实际接触点值得记：① 设备上若预装了 MTK 工程 App（EngineerMode / MTKLogger），可在 PDA 侧触发日志收集辅助排障；② 产线首次烧录/写号由 SP Flash Tool + SN Writer 完成，PDA 出厂前 IMEI/SN 已落 NVRAM，App 层读 imei/serial 即可，不要试图在 App 层写。
  • scatter 与 firehose 的本质差异：MTK 用文本 scatter.txt 描述分区表（人类可读、易改），高通用 prog_*.elf firehose 程序在设备端解析——前者 PC 端逻辑重，后者设备端逻辑重。
  • DA 与安全：DA_SWSEC.bin 是带安全校验的 Download Agent；Secure Boot 开启后必须用授权 DA，否则握手失败，这正是防非法刷机的第一道闸。
