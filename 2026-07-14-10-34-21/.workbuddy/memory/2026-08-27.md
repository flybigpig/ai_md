## 运行验证（本机 Windows 环境踩坑记录，重要）
- 本机 Rust 装在 `C:\Users\YTO-02231406\.cargo\bin`，但非交互 shell 的 PATH 没它；rustup 已装但**无默认 toolchain**。
- 本机**没有 MSVC 的 cl/link**（VS2022 只装了不带 C++ 工作负载的版本），但有 **MinGW gcc 15.2**：`C:\D\minGw\mingw64\bin\gcc.exe`。
- 解决：装 GNU toolchain 并用 mingw gcc 当链接器：
  `rustup default stable-x86_64-pc-windows-gnu`（装出 rustc 1.98.0）。
- cargo 环境变量坑（关键）：
  - cargo 是 Windows 原生 exe，**不认 `/c/...` msys 路径**；`--manifest-path /c/...` 报 “does not exist”。必须 `cd` 进目录后用相对命令。
  - 链接器路径若写成 `/c/D/minGw/.../gcc.exe` 会被 cargo 再加一层 `C:` 变成 `C:/c/D/...` 而找不到；必须给 **Windows 原生盘符路径** `C:/D/minGw/mingw64/bin/gcc.exe`。
  - 必要环境变量：`CC` / `CXX` / `AR` / `CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` / `CARGO_TARGET_X86_64_PC_WINDOWS_GNU_AR` 全部指向上述 mingw 原生路径；`PATH` 加 `C:/D/minGw/mingw64/bin`（提供运行时 dll）。
- 代码修正：`CreateUser` 补 `#[derive(Serialize)]`（客户端 POST 要序列化）；server 的 `post/put/delete` 自由函数导入多余（链式 `.post()` 用的是方法），去掉只留 `get`。
- 结果：`cargo build --bins` 通过，`server.exe` 起在 127.0.0.1:3000，`client.exe` 实测 POST/GET/404 全部符合预期。
- 一键复跑（在 rust-http-demo 目录内）：
  `export PATH="/c/D/minGw/mingw64/bin:$PATH" CC=C:/D/minGw/mingw64/bin/gcc.exe AR=C:/D/minGw/mingw64/bin/ar.exe CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER=C:/D/minGw/mingw64/bin/gcc.exe CARGO_TARGET_X86_64_PC_WINDOWS_GNU_AR=C:/D/minGw/mingw64/bin/ar.exe; ./target/debug/server.exe & ./target/debug/client.exe`
